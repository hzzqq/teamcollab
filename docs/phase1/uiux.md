# 团队协作工具 MVP — UI/UX 设计方向（Phase 1）

> 生成日期：2026-08-05 | 设计师：颜好看 | 阶段：Phase 1 设计调研
> 三轴刻度：Variance=6 / Motion=3 / Density=7
> 寄存器：Product（设计服务产品，标杆 = 赢得熟悉感）
> 目标团队：20-100 人中型团队 | 主场景：任务/项目管理（看板 + 任务 CRUD + 成员协作 + 权限）

## 1. 竞品 UI 方案分析

### 1.1 Linear（深色高对比标杆）
- **布局**：左侧 Sidebar 导航 + 主内容区多视图（列表/看板/时间线/分屏），顶部视图标题栏承载筛选与显示选项，侧板承载任务元数据
- **配色**：近纯黑背景 `#08090A`，面板 `#1A1C1F`，前景 `#FFFFFF`，次级文本 `#B4BCD0`，边框 `#282A2F`；强调色极少——靛蓝 `#5E6AD2` + 三个状态色点（蓝 `#4EA7FC` / 绿 `#4CB782` / 红 `#EB5757`）
- **信息密度**：极高。紧凑行高、表格化布局、状态用色点而非色块、键盘快捷键驱动（Cmd+K、快速创建）
- **主题系统**：三变量生成（base 色 + accent 色 + contrast 比例 → 98 色），LCH 色彩空间，层级用亮度递进表达而非阴影
- **可借鉴**：克制的色彩点缀、边框而非阴影表达层级、键盘优先、高密度排版

### 1.2 Asana（清爽浅色标杆）
- **布局**：左右分栏——左侧项目树状目录 + 右侧任务详情；任务卡片带状态标签、责任人头像、截止日期
- **配色**：白底 + 浅灰分层，品牌紫罗兰作点缀；整体清爽、现代、层级清晰
- **信息密度**：中高。任务列表紧凑但留白充足，状态用彩色标签
- **可借鉴**：浅色模式的分层方式、任务卡片的信息组织（状态/负责人/截止日期一屏可见）

### 1.3 Notion（极简内容优先）
- **布局**：内容块自由排版，数据库多视图（表格/看板/画廊）
- **配色**：白底黑字 + 少量高亮色块，圆角卡片 + 柔和阴影
- **信息密度**：中低。留白多，内容优先
- **可借鉴**：内容与操作的清晰分离（不借鉴其低密度与自由排版，MVP 需要确定性）

### 1.4 Trello（看板经典）
- **布局**：纯看板，卡片即任务，横向滚动列
- **配色**：色块标签分类，明快活泼
- **信息密度**：中。卡片大、留白多
- **可借鉴**：看板交互模式（拖拽、列切换）；不借鉴其轻量视觉（对 20-100 人团队太单薄）

### 1.5 Monday.com（可视化强、色彩活泼）
- **布局**：卡片式 + 多视图（表格/看板/甘特），色彩编码 + 进度条
- **配色**：多色主题，色彩丰富
- **信息密度**：中
- **反例警示**：色彩过活跃、卡片过"玩具感"，不符合"视觉专业度"诉求，仅作反面参照

### 竞品对比矩阵

| 维度 | Linear | Asana | Notion | Trello | Monday |
|---|---|---|---|---|---|
| 主题 | 深色为主 | 浅色 | 浅色 | 浅色 | 多色 |
| 信息密度 | 极高 | 中高 | 中低 | 中 | 中 |
| 色彩克制度 | 极克制 | 克制 | 克制 | 活泼 | 活跃 |
| 键盘效率 | 极强 | 中 | 弱 | 弱 | 中 |
| 圆角 | 小(4-8px) | 中(6-10px) | 大(10-14px) | 大 | 大 |
| 层级表达 | 边框+亮度 | 边框+阴影 | 阴影 | 阴影 | 色块 |

## 2. 对标品牌与设计语言（选定）

**主对标：Linear（深色克制、键盘效率、高信息密度）**
**次对标：Asana（浅色分层、任务信息组织）**

### 选择理由
1. **用户诉求精准匹配**：B2B SaaS 生产力工具、重视信息密度/操作效率/视觉专业度、厌恶空洞 UI → Linear 正是"信息密度 + 操作效率 + 克制专业"的行业天花板，其浅色主题也直接对标 Asana 的清爽分层
2. **P0 规则友好**：Linear 的单一强调色 + 低饱和状态色，天然规避"紫色渐变 + 发光 + 毛玻璃"AI 模板套路；以边框和亮度表达层级，与"禁硬编码颜色/禁千篇一律 Hero"完全兼容
3. **差异化**：国内团队协作工具（Teambition/飞书/钉钉）清一色浅色活泼风。以 Linear 式克制 + 深色主题能力形成辨识度，同时默认浅色保障 20-100 人团队的普适接受度
4. **学习价值**：练手项目对标一流设计语言，可直接吸收 Linear 的"三变量主题"思想（用 Token 简化实现）与 Asana 的任务信息组织模式

### 不选理由
- 不选 Notion：MVP 需要确定性布局，其自由排版与低密度不符合效率诉求
- 不选 Trello：视觉单薄，无法支撑 20-100 人协作的复杂度
- 不选 Monday：色彩过活泼，违背"视觉专业度"

## 3. 配色方案（Design Token 草案）

> 遵循四层 Token 架构（A1 身份层 → A2 语义层 → B 插槽层 → C 扩展层）。
> 单一强调色策略（对照 color-palettes.md 第 1 套「SaaS 通用信任蓝」并收敛），不做 3+ 高饱和色。
> 语义色用通用语义（success=绿 / warn=琥珀 / danger=红），不套用 A 股红涨绿跌。

### 3.1 A1-Identity 品牌色（Indigo / Slate Blue 家族，纯色使用，非渐变）

| Token | 值 | 用途 |
|---|---|---|
| `--color-primary-500` | `#6366F1` | 辅助强调（选中态、链接 hover） |
| `--color-primary-600` | **`#4F46E5`** | **品牌主色（Primary）** |
| `--color-primary-700` | `#4338CA` | Primary hover |
| `--color-primary-800` | `#3730A3` | Primary active |
| `--color-primary-50` | `#EEF2FF` | Primary 浅底（选中背景、按钮次级底） |

> 说明：选择 Indigo-600 `#4F46E5` 而非 Tailwind 默认强调色 `#6366F1`，主色更沉稳、更具 B2B 信任感；`#6366F1` 仅作为次级强调。品牌色在深/浅主题中一致，仅前景与层级不同。

### 3.2 A1 中性色（浅色主题 — 默认）

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#F8FAFC` | 页面背景 |
| `--surface` | `#FFFFFF` | 卡片/面板/侧栏背景 |
| `--surface-warm` | `#F1F5F9` | 次级面板、hover 行 |
| `--fg` | `#1E293B` | 主文本 |
| `--fg-2` | `#475569` | 次级文本 |
| `--muted` | `#64748B` | 辅助文本/占位 |
| `--meta` | `#94A3B8` | 三级元数据（时间戳等） |
| `--border` | `#E2E8F0` | 默认边框 |
| `--border-soft` | `#F1F5F9` | 内部行分隔 |

### 3.3 A1 中性色（深色主题 — 可切换，Linear 风格）

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0D1117` | 页面背景 |
| `--surface` | `#161B22` | 卡片/面板背景 |
| `--surface-warm` | `#21262D` | 次级面板、hover 行 |
| `--fg` | `#F0F6FC` | 主文本 |
| `--fg-2` | `#D0D6E0` | 次级文本 |
| `--muted` | `#8A8F98` | 辅助文本 |
| `--meta` | `#484F58` | 三级元数据 |
| `--border` | `#282A2F` | 默认边框 |
| `--border-soft` | `rgba(255,255,255,0.05)` | 内部行分隔 |

### 3.4 A2 语义色（通用语义，深浅主题各自适配）

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--success` | `#16A34A` | `#3FB950` | 已完成、在线、成功 |
| `--warn` | `#D97706` | `#D29922` | 即将到期、警告 |
| `--danger` | `#DC2626` | `#F85149` | 已逾期、删除、错误 |
| `--info` | `#2563EB` | `#58A6FF` | 通知、提示 |

### 3.5 C-extension 状态标签色板（Linear 式色点，仅用于状态/优先级/标签）

低饱和、小面积使用，每屏标签色 ≤ 3 处可见，避免视觉噪音：

| Token | 值 | 用途示例 |
|---|---|---|
| `--tag-blue` | `#4EA7FC` | 标签（研发） |
| `--tag-green` | `#4CB782` | 标签（已完成类） |
| `--tag-amber` | `#D29922` | 优先级高 |
| `--tag-purple` | `#A78BFA` | 标签（设计） |
| `--tag-rose` | `#F76B8A` | 标签（紧急） |

### 3.6 色彩纪律
- 每屏强调色（Primary）可见使用 ≤ 2 处：CTA 按钮 + 选中态
- 中性色占 70-90%，强调色 5-10%，语义色 ≤ 5%，效果色 < 1%
- 状态优先级展示：**色点/小徽标**，不铺大面积色块
- 深色层级用亮度递进（`#0D1117 → #161B22 → #21262D`），不用阴影堆叠
- 禁止 `#000` 纯黑、`#808080` 纯灰直用；所有颜色经 Token 引用

## 4. 字体搭配

| 角色 | 字体栈 | 用途 |
|---|---|---|
| Display / Body | `Inter`, `Noto Sans SC`, `-apple-system`, `sans-serif` | 标题 + 正文（中文回退 Noto Sans SC） |
| Mono | `JetBrains Mono`, `Fira Code`, `monospace` | 任务 ID（如 ENG-2703）、数字、代码片段 |

- **Google Fonts @import**：
  ```css
  @import url('https://fonts.googleapis.com/css2?family=Inter:wght@400;510;590&family=JetBrains+Mono:wght@400;500&family=Noto+Sans+SC:wght@400;500;700&display=swap');
  ```
- **字重三级**：Regular 400（正文）/ Medium 510（按钮、表头、小标题）/ Semibold 590（大标题、强调）
- **字号阶梯（8 级）**：12 / 14 / 16 / 18 / 20 / 24 / 32 / 40px
  - 表格/列表正文 14px、辅助 12px、看板卡片标题 14px、页面标题 20-24px
- **字距**：ALL CAPS ≥ 0.06em；标题 -0.01 ~ -0.02em；正文 0
- **行高**：正文 1.5；标题 1.2-1.3
- 反 AI 模板提醒：Inter 作正文字体可用，但不作为"展示字体"宣称高级——本产品是工具，Inter 的克制正是对的

## 5. 风格基调

### 5.1 信息密度：高（Density=7）
- 紧凑 4px 网格（4/8/12/16/20/24/32/48）
- 看板列宽 272px，卡片高度紧凑（标题 + 状态点 + 负责人头像 + 截止日期一行）
- 表格为默认视图之一：筛选栏 + 列表 + 分页；列可排序
- 键盘快捷键优先：`Cmd/Ctrl+K` 全局搜索、`C` 快速创建任务、`←/→` 切换看板列、`Enter` 编辑
- 列表/表格用 `divide-y` 与 `border` 分隔，不用大圆角卡片堆叠（Density=7 时禁止通用卡片容器滥用）

### 5.2 圆角：小圆角（Linear 系）
- `--radius-sm` 4px（Badge、Tag、输入框）
- `--radius-md` 8px（按钮、看板卡片、列表行）
- `--radius-lg` 12px（卡片/弹窗）
- `--radius-pill` 9999px（头像、状态点）
- **上限 12-16px**，杜绝 ≥24px 的"AI 过度圆滑"

### 5.3 阴影：极简（边框优先）
- 默认层级用 `1px border`（`--elev-ring`），几乎不用阴影
- `--elev-raised` 仅用于：弹窗、下拉菜单、拖拽中的看板卡片
- 禁用"幽灵卡片"（1px 边框 + blur ≥16px 阴影同体）

### 5.4 布局模式（SaaS B2B 标准）
- **左侧 Sidebar（240px）**：工作区导航（收件箱/我的任务/项目/看板/成员/设置），图标 + 文字，可折叠
- **顶部视图栏**：面包屑 + 视图切换（看板/列表）+ 筛选/排序 + 主操作按钮（新建任务）
- **主内容区**：看板（横向滚动列）或列表（表格），任务详情用右侧滑出面板（Drawer）而非整页跳转
- **移动端（<768px）**：Sidebar 收为底部 TabBar，看板列单列堆叠，Drawer 全屏

### 5.5 动效：功能性（Motion=3）
- 全部 ≤ 300ms，基准 150ms
- 只用于传达含义：拖拽卡片跟随（200ms）、Drawer 滑出（250ms）、hover 状态（150ms）
- 无装饰性动画；支持 `prefers-reduced-motion`
- 禁止弹跳缓动、禁止 >1s 动画

### 5.6 5 态覆盖（每个核心组件强制）
- **看板列**：Loading（列骨架）/ Empty（"暂无任务，创建第一个"）/ Error（加载失败重试）/ Populated（任务卡片）/ Edge（列超长可滚动、任务标题截断）
- **任务卡片**：Default / Hover（border 高亮）/ Active（拖拽中 raised 阴影）/ Loading（拖拽 placeholder）/ Edge（标题超长省略）
- **表格列表**：同上 + 批量选中态

## 6. 浅色 / 深色主题建议

**结论：默认浅色 + 完整深色主题（可切换，Token 双主题）**

- **默认浅色**：20-100 人团队含产品/运营/市场等非工程师成员，浅色全天候可读性最佳；以 Asana/Notion 的清爽 + Linear 的克制严谨融合
- **深色主题**：完整实现（Linear 色板），作为"专业/专注"主题供开发者与夜间用户切换；深色是品牌辨识度资产，也是练手学习主题 Token 化的最佳实践
- 两主题共用同一套语义 Token，仅切换 A1 中性色与 A2 语义色映射；品牌 Primary 两主题一致
- 主题实现方式：`data-theme="dark"` 属性切换 CSS 变量（参考 token-standard 深色规范），不硬编码两套组件样式

## 7. 图标库推荐

**推荐：Lucide Icons（https://lucide.dev）**

### 理由
1. **Feather 的正统继任者**：Feather 已停止维护，Lucide 由同一社区延续并活跃迭代（周更），可持续性最佳
2. **统一描边风格**：默认 2px stroke、圆角端点，与 Linear 的线性图标气质一致；支持按需调整 `stroke-width`（本产品统一 1.5px 更精致）
3. **MIT 许可 + 树摇优化**：按需引入，零运行时开销，前端友好
4. **框架全覆盖**：官方 React / Vue / Svelte / 原生 SVG 包齐全，适配架构师锁定栈
5. **克制统一**：相比 Tabler（2000+ 图标风格参差）、Material（双色/填充混杂），Lucide 一套 1500+ 图标风格高度统一，最契合"克制专业"基调

### 备选
- Feather（风格同源但已停维护，不推荐）
- Tabler（图标量大，但风格不统一、偏花哨，违背克制基调）

### 尺寸规范（全项目统一）
| 尺寸 | 场景 |
|---|---|
| 16px | 行内图标、表格内操作、状态点旁 |
| 20px | 按钮内图标、输入框前缀/后缀 |
| 24px | 独立图标、空状态插画、Sidebar 导航图标 |

### 禁用
- 禁止 emoji 作功能图标（P0）；所有图标走 Lucide SVG，`fill="none"` + `stroke="currentColor"`
- 图标颜色一律继承文本色或 Token（`currentColor`），不单独硬编码

## 9. 反模式自查（对照 P0 与行业规范）

- 通过：无 emoji 作功能图标（Lucide 统一 SVG）
- 通过：无紫色→粉色渐变（品牌色为纯 Indigo `#4F46E5`，同色系深浅渐变仅用于 hover 态，非主视觉）
- 通过：无空洞占位文案（空状态全部带引导 CTA）
- 通过：无硬编码颜色（全部 Token 引用）
- 通过：首屏展示真实产品内容（看板视图即产品本身，不做"大标题 + 抽象 3D"Hero）
- 通过：非默认 Tailwind 靛蓝强调（主色用 Indigo-600 而非 `#6366F1` 默认）
- 通过：无侧条纹边框、无渐变文字、无装饰性毛玻璃、无重复卡片网格
- 通过：圆角 ≤ 16px、阴影仅用于弹层
